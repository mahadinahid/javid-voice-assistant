# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Rules that override your instincts

- **The voice is permanent: `en-US-AndrewNeural` via edge-tts, everywhere (web UI and CLI), and nothing else** — except in Bangla mode, which the user asked for on 2026-10-14 and which uses `bn-BD-PradeepNeural` (`EDGE_VOICE_BN`), locked the same way. The user approved Andrew as "perfect" (2026-10-13) and made it permanent (2026-10-14: "set this voice for everything… don't change it again"). There is deliberately no other engine and no fallback voice: no browser speech, no macOS `say`, no Groq TTS. If edge-tts fails, the reply is shown as text with a visible "voice unavailable" notice. Never add a substitute voice or change `EDGE_VOICE`/`EDGE_VOICE_BN`, not even to fix latency or outages, unless the user explicitly tells you to. Upgrading the `edge-tts` library is fine. (Details under *Speech* below.)
- **The app runs on real data**: `tasks.txt`, `memory/USER.md` + `memory/MEMORY.md`, `chat_log.jsonl`, a connected Google Calendar, and the user's API keys in `.env`. See *Testing safely*.
- **Quota is scarce.** Groq's free tier caps each model at 200k tokens/day (a turn is ~2 requests; real turns to 2026-10-22: median 3.3k tokens, mean 4.6k, from `llm_turns.jsonl`); Gemini's free tier is 20 requests/day. Don't loop LLM tests, and never run the full live suite (`--llm`) casually: one run costs more than gpt-oss-20b's whole day (below).
- **`personal_ok` in `config/providers.yaml` is Mahadi's to set** (2026-10-25: "I will set those flags myself after reading each data policy"). Never set one to true in the real file, not even to make a test or a demo work: the suite uses its own scratch copy. While none is true, calendar, task, memory and past-chat requests are refused and other turns go out without memory or chat history; that is intended (see *Providers, budgets and privacy*).

## Running and checking

```bash
source .venv/bin/activate
python server.py                 # web UI at http://localhost:8000 — the main way the app is used
python javid.py                  # original terminal push-to-talk loop (Enter to record/stop)
lsof -ti tcp:8000 -sTCP:LISTEN | xargs kill   # stop the server (only the listener; plain :8000 also kills browser tabs' connections)
PYTHONUNBUFFERED=1 python server.py   # when debugging: [tool]/[retry]/[llm]/[tts]/[hands-free] lines are plain prints
```

There is no linter or build step. `index.html` is one hand-written file (inline CSS + JS, no framework). Syntax-check its main script with this (it starts at the first bare `<script>`; the small `<script id="theme-boot">` in `<head>` comes first, so the end must be searched from there or the check silently reads nothing):

```bash
python3 -c "s=open('index.html').read(); i=s.index('<script>'); open('/tmp/ui.js','w').write(s[i+8:s.index('</script>', i)])" && node --check /tmp/ui.js
```

**`python regression.py` is the behaviour check** — 156 cases: 93 scripted ones that are the default run, and 63 prompts through the real LLM and tool loop that run only with `--llm`. All of them use scratch task/memory/history/timer/watch files, a scratch provider registry (every provider `personal_ok`, except where a privacy case says otherwise) and usage ledger, a fake in-memory calendar, a fake Tavily and a fake Google News with fixed results, and fake weather and price APIs (your tasks, memory and calendar are never touched and no Tavily credits are spent; the live cases' real requests are still counted in `llm_usage.jsonl` and `data/providers.db` because they're really spent). **The default run never reaches a real API**: every socket to anything but this machine is refused (`NetworkBlocked`), and a case that tries fails; provider responses come from `fixtures/providers/` (recorded where possible, the providers' documented formats otherwise; its README says which). The `client_script` cases run the real model router (budget guard, cooldowns, privacy rule) against a fake provider (`FakeLLM`, which also rejects a call to a tool it wasn't offered, as Groq does) and check what each request carried. Run it before/after prompt, tool or agent-loop changes. Each case's line ends with its time per turn and tokens; the web, weather and price services are fakes, so the time is the model's plus Javid's own (per-minute 429 waits are left out: the suite's Groq client hands 429s to its own handler instead of retrying them inside the SDK).

```bash
python regression.py                                       # the default: the 93 scripted cases, no network, no tokens, ~5 s
python regression.py -k "delete needs"                      # one case (substring of its name)
python regression.py --llm                                  # also the 63 live model cases (real requests: see below)
python regression.py --llm -k "task: add" -v                # one live case, show every reply
python regression.py --llm -n 3                             # repeat each case (model is non-deterministic)
python regression.py --use-120b                             # live cases on gpt-oss-120b (default: gpt-oss-20b alone)
python regression.py --models gemini:gemini-3-flash-preview # that chain only, no Groq fallback masking failures
python regression.py --live                                 # smoke test: one real call per provider that's on, then stop
```
(`--offline` is still accepted: it's the default now.)

The suite always runs on **one model with no fallback**: gpt-oss-20b by default; 120b (the live chain's backup) only with `--use-120b`. It warns up front when `daily_left()` says the model can't afford the run (2,800 tokens a turn). **A full live run is ~175 LLM requests and ~210k tokens** (measured 2026-10-24: 76 live turns at 2,785 tokens and 2.3 requests each): more than gpt-oss-20b's 200k a day, so afterwards the live Javid runs on its backup for hours. Run the live cases you touched with `--llm -k`; the default run covers everything scripted. `--live` (2026-10-25) uses the real registry, chain and keys: one real call per provider that is on and that the budget guard allows (a ~20-token chat on each model provider's first model, so one of Gemini's 20 requests a day; one Tavily search credit; the others' cheapest call once their keys exist), each counted in the real ledger as `op: smoke`, and prints what each has used of its allowance. A run ends with average tokens per turn and the run's total tokens (`--tokens-out FILE` saves every turn's counts, for before/after comparisons). Exit code 0 = all passed, 1 = a check failed, 3 = inconclusive (429/network — never reported as a pass or fail). Per-minute 429s are waited out; a longer wait stops the suite.

Setup needs `GROQ_API_KEY` in `.env` (also used for speech recognition). `TAVILY_API_KEY` enables web search (without it `web_search` says it isn't set up). `GEMINI_API_KEY` / `DEEPSEEK_API_KEY` / `IFM_API_KEY` are optional. Every provider and the variables it needs are listed in `config/providers.yaml`; one without its key (or turned off there) is off, and the server and CLI print which are on at start (`[providers] enabled: …`, names only). `TELEGRAM_BOT_TOKEN` (a bot made with @BotFather; the ✈ Telegram page saves it) turns on the Telegram bot and `TELEGRAM_ALLOWED_IDS` (comma-separated Telegram user ids; pairing fills it in) says who may use it; voice-note replies there need `ffmpeg` (Homebrew), the pairing QR code `segno`. `README.md` describes only the original CLI version (10 tools; it still mentions macOS `say`, which is gone); the web UI, calendar, hands-free and model chain are documented here.

## Architecture

**`javid.py` is the shared core** for the CLI and the web server: tool implementations, `TOOLS` schemas / `TOOL_MAP` dispatch, conversation state (module-level `messages`), STT (`transcribe`), TTS (`synthesize`; the CLI's `speak` plays the same audio with `afplay`), the LLM provider chain, and the agent loop. `server.py` (FastAPI) and `index.html` wrap it; `calendar_tools.py` adds the Google Calendar tools.

### Agent loop — `think_stream(user_text)`
A generator yielding `("tool", name)`, `("say", text)` (spoken, not part of the reply: "Searching…"), `("sources", links)` and `("delta", text)`; `think()` joins the deltas (CLI). Behaviours that aren't obvious:
- Up to `MAX_TOOL_ROUNDS` tool rounds per turn (plus one for a web rewrite); the last round is sent with no tools, so the model has to answer instead of ending on "I got stuck". Tool results do the follow-up work so the model needn't spend a round on it: `add_task` reports the new number, the pending count and likely duplicates; `complete_task`/`delete_task` accept words from the task as well as its number.
- Each round's text is **buffered** and emitted only if that round made no tool calls — text alongside a tool call is the model guessing before it saw results.
- One retry each for an empty reply, for an `APIError` (malformed tool-call JSON), and for a **garbled** reply; a second garbled reply becomes a short apology. `_is_garbled` checks the whole reply and, separately, a skill's or agent's SPOKEN and SCREEN parts (a long screen list used to dilute a garbled spoken part); `_degenerate` flags mostly dots (not those inside numbers), 3+ punctuation-only tokens in a row ("… … …"), a reply chopped into ellipsis fragments, fragments that repeat or restart the previous one ("I'm… I'm not… I'm not sure…"), a 2–6-word phrase three times running (one word four times: "no, no, no" is speech), or one word on repeat. The first check alone caught the 2026-10-13 reply (gpt-oss-120b) but none of those other shapes. Agents check their own answer (`garbled` in `agents.configure`): a garbled answer is asked for once more, then the agent reports it couldn't finish; a garbled rewrite is ignored. Garbled assistant messages are also skipped when a chat's context is loaded. The scripted `garble:` cases in `regression.py` hold the exact 2026-10-13 text.
- `finally` appends the reply to `messages` and `chat_log.jsonl`, so aborted streams still record what was said. The reply keeps its **basis**: the tools the turn used (`tools`: the model's calls, a code answer's tool events via `_relay`, an agent's) and its links (`sources`, with `via: "Google News"` on Google's headlines); `open_session` reloads both, so `selfcheck` can say where an answer came from after a restart.
- **Answered in code, before any LLM request** (in this order, after the memory yes/no and the language switch): `selfcheck.request` (a self-check, or where the last answer came from), `about.answer` (questions about Javid), then `_code_answer`: `watches.request`, `rates.request`, `markets.brief_request`, `news.request`. Each takes a message only if it can answer all of it; anything else goes to the model. A code answer that raises hands the turn to the model.
- **Agents** (see below): a tool may return a generator (`delegate`); `think_stream` relays its events (`agent`, `tool`) with `yield from` and takes its return value as the tool result. The agent's answer (`agents.take_handoff()`) is then used as the next round's reply as it is — no request to reword it (`via_agent` keeps its screen part and skips `MAX_SENTENCES`). A request matching a required agent's triggers (`agents.required_agent`) gets its delegate call made in code (`forced`, with the last two turns via `_agent_task`): gpt-oss-20b offered only `delegate` still reached for other tools, and once widened called `use_skill("planner")`.
- **Token budget per request** (measured 2026-10-14 with `regression.py`: 3,859 → 1,873 tokens per turn):
  - `SYSTEM_PROMPT` is **static** so the provider's prefix cache hits; keep anything that changes out of it. Today's date, the 14-day weekday table and the older-chat summary go in `context_block()`, prepended to the newest user message only. The memory files go in a fixed `[Memory]` block appended to the system message (`memory_store.block()`): it only changes when an entry does, so the cache still hits. The clock time is deliberately left out: time questions must go through `get_datetime`.
  - `select_tools()` sends only the `TOOL_GROUPS` whose regex matches the message (calendar is split: read = `list_events`/`find_free_time` ~270 tokens, write = add/move/delete ~570, so "what's on tomorrow" doesn't carry the write tools), plus groups used in the previous turn (follow-ups like "yes"); nothing matched = every tool, small talk = none. If the model calls a tool it wasn't sent (Groq: "not in request"), the round is retried with every tool. Rules for one tool belong in its description, which only travels with it — but the calendar rules stayed in the system prompt: in their descriptions alone, gpt-oss-120b listed events instead of calling `delete_event` and asked before adding.
  - `_request_messages()` builds each request: the last `HISTORY_TURNS` (6) turns as plain user/reply pairs (earlier turns' tool calls and results are dropped), plus a one-line Python summary of older turns (`_summarize`, no LLM call). `messages` itself still holds the full session.
  - **Carried tool facts** (`_facts_note`): because of that, a follow-up only saw the model's own earlier reply and it repeated its own wrong date over the tool's (2026-10-15, Durga Puja). The latest result of each `FACT_TOOLS` tool (`list_holidays`, `list_events`, `find_free_time`) from the last `FACT_TURNS` (3) turns goes in the `[Context]` note, clipped to `FACT_CHARS`, marked as outranking earlier replies; a later calendar write drops the calendar reads. Built from `messages`, so it's empty right after a restart.
  - **Budget guard** (`_models_to_try` → `providers.state`; 2026-10-25): Groq's daily limit is a bucket refilling at limit/24h per second, not a midnight reset; `daily_left()` replays `llm_usage.jsonl` through it from Groq's last "Used N" report (`llm_quota.json`), and `_groq_usage` hands the guard the fuller of that and requests per day from the `x-ratelimit` headers (a reading older than its reset time counts as refilled). At 80% of an allowance a model is in **reserve**: tried only after the ready ones, on every turn (before 2026-10-25 web and reasoning turns still used it first; `is_heavy_turn` is gone). At 95% it is **off**: not tried until it refills. A model resting after a 429 isn't tried before its retry-after either, and when no model is left Javid says so (`NoModelReady`, `PHRASES["no_model"]`) instead of sending anyway. The Providers panel shows 🛡 reserve and ⛔ off.
  - Per-turn totals go to `llm_turns.jsonl` (`_finish_turn_usage`); the Providers panel shows each model's average over its last `TURN_AVG_WINDOW` turns. `regression.py` redirects that file to scratch so the panel reflects real use only.

### Adding a tool
Implement it, add a schema to `TOOLS` (put its usage rules in the description), add a lambda to `TOOL_MAP`, and add it to a `TOOL_GROUPS` entry with words that should trigger it — otherwise it's only sent when no group matches. Calendar tools live in `calendar_tools.py`, which exports its own `TOOLS`/`TOOL_MAP` that `javid.py` splices in; they're wrapped in `_guard`, which turns auth/API errors into sentences the model can speak. So do `weather.py`, `timers.py`, `calc.py`, `markets.py` and `agents.py`. To give an agent a tool, add it to the agent's `allowed-tools`. A tool that changes Mahadi's data goes in `javid.WRITE_TOOLS` and needs a `_plan`/`run` branch in `approvals.py`, or Telegram would run it without a button. A tool whose result is his calendar, memory, chat history or tasks goes in `javid.PERSONAL_TOOLS` (the privacy rule), and a new outside service with a key or an allowance gets an entry in `config/providers.yaml` and goes through `providers.allow`/`record` (below).

### Web search (`web_tools.py`, Tavily)
`web_search(query, recency_days, domains)` is a basic-depth search, up to 5 results. News-looking queries (or any `recency_days`) use the news topic with a `days` filter (default 7). `read_page(url)` is Tavily extract, and accepts only the top 3 results of a search made this turn (a result number or a same-site URL also resolves, because models rewrite URLs), with at most 3 reads per turn. The rules are enforced in code, in `think_stream` via `web_tools.check_reply`/`finalize`, not just prompted:
- Rates and prices in the answer (currency or % figures, plus any bare number a source gives as one) must appear on an official domain (`is_official`: gov/gob/gouv/mil/int, or `OFFICIAL_DOMAINS`) or on two sites. If figures for the same thing differ between sites (`_rivals`), the answer must say the sources disagree. A failing answer gets one rewrite. That draft and its note go into requests only, never `messages`. If the rewrite still fails, `finalize` replaces the answer with "couldn't confirm" or prefixes "The sources disagree on this." — but only when the question asked for a figure (`_FIGURE_ASK` in javid.py: rate, price, how much, %…; `figure_asked`). Otherwise just the sentences with the unconfirmed figure go (2026-10-22: "Bring me some news from AI development" was replaced whole by "I couldn't confirm a specific growth figure").
- **Search engines aren't sources:** `domains` given as news.google.com, google.com, bing.com, news.yahoo.com, msn.com… are dropped (`_search_engine`; finance.yahoo.com stays), and with nothing else named the search covers every site (2026-10-24: `domains=["news.google.com"]` found only Google's topic pages, and "an AI attack in PHP" got "I couldn't find any recent news").
- **Tavily down or out of credits:** a news-looking `web_search` answers from Google News' headlines instead (`_google_fallback`: titles only, marked as such for the model; 2026-10-22 a Tavily ConnectionError became "I couldn't reach the news sites right now"). `news_headlines` and `headline_items` use Google News first and Tavily only for a topic it couldn't give (below).
- `finalize` keeps a web answer to `MAX_SENTENCES` (3, counted with the same boundary rule as `feedSpeech`) and appends "Source: <name>, <date>." if the answer doesn't already name a source and give a date — except on a nothing-found answer with no figures (`_NOTHING_FOUND`: "the rates aren't available right now" used to get "Source: Bangladesh Bank"). Results without a published date use "retrieved <today>".
- The same normalized query within 15 minutes is served from `_cache` (no credit). A paid call goes through the budget guard first (`providers.allow`: Tavily's free 1,000 credits a month, reserve at 80%, off at 95% until the 1st) and then `DAILY_CREDIT_CAP` (40/day, local midnight, Javid's own). Every call, cache hits too (0 credits), is a row in the usage ledger in credits (Tavily's `usage.credits`, else its `costs` entry); a 429 rests Tavily until its retry-after and a plan limit (432/433, which tavily-python raises as `ForbiddenError`) until the 1st of the month. `tavily_usage.jsonl` was the log until 2026-10-25 (the ledger imported it once). Before all that, a query carrying personal data isn't sent at all (`_private`, the privacy rule below), nor handed to the Google News fallback.
- Links travel in the `sources` NDJSON event and are stored on the chat_log entry, so history shows them too. They're never spoken. `esc()` in `index.html` escapes quotes because URLs go into `href`.

### Skills (`skills.py`, `skills/<name>/SKILL.md`)
agentskills.io layout: frontmatter `name` (= folder name), `description` (when to use it), optional `allowed-tools` (space-separated) and `metadata` (`spoken-seconds`, `triggers` regex); the body holds steps, tools and output format. Only names + descriptions go into `SYSTEM_PROMPT` (`prompt_index()`, built once at import, so the prompt stays static — restart after adding a skill). `use_skill` is sent when a skill's `triggers` match (a `TOOL_GROUPS` entry); calling it returns the body, emits a `skill` event (sidebar highlight) and unlocks the skill's `allowed-tools` for the rest of the turn. A skill with `required: "true"` in its metadata (news-digest — morning-brief's "headlines" trigger also matches plain news questions) joins `REQUIRED_TOOLS`: a reply to its triggers without `use_skill` gets one retry (gpt-oss-120b answered "yuan rate in taka" from four web searches, when exchange rates were a skill), and the turn is sent without `WEB_TOOLS` (also when widening after "not in request"). A skill reply has `SPOKEN:` and `SCREEN:` parts: `split_reply` separates them, `trim_spoken` cuts the spoken part to whole sentences within `spoken-seconds` (2.3 words/s), the screen part goes out as a `screen` event (shown under the bubble, stored as `screen` in chat_log, never spoken). Web answers inside a skill skip `MAX_SENTENCES` (the skill's budget applies) but keep the figure checks, run on spoken + screen; the rewrite note asks only to drop the figure (`correction(..., in_skill=True)`: a 3-sentence rewrite cut a digest from 13 stories to 7), and if it's still there `finalize` drops just the sentences carrying it, and appends no single source to an answer that names its own.
- `morning-brief`: `morning_briefing` + `news_headlines(["Bangladesh","China","AI"])` (one tool call; Google News per topic, top story each) → ≤45 s spoken, full version on screen.
- `news-digest` (required): many stories at once. Since 2026-10-24 a message that is only a news request is answered in code (`news.py`, below), so the skill gets what's left: news plus something the code can't do ("…and your take on them", a story by name). One `news_headlines` call: up to `MAX_NEWS_TOPICS` (8) topics × `per_topic` (≤3) stories; its lines are `N. Topic - headline (source, date)` so the fallback screen reads well. ≤60 s spoken, the full numbered list on screen.

### Weather, timers, calculator, live prices (2026-10-19)
All free, no keys; everything is computed and worded in Python, the model only relays it (each module exports `TOOLS`/`TOOL_MAP` and has its own `TOOL_GROUPS` entry). The system prompt says weather, prices and sums come only from these tools.
- `weather.py` — `get_weather(place, day, days)`: Open-Meteo (current, hourly rain chance, high/low, UV, sunset); when it fails (its forecast API was "overloaded" for an afternoon on 2026-10-19), MET Norway (rain amounts, not chances; high/low computed from its hourly series; needs the identifying `USER_AGENT`), and Open-Meteo is skipped for 10 min. Places via Open-Meteo geocoding (Bangladesh first when no country is given); home is Dhaka (`HOME`, no lookup). `morning_briefing` now includes `brief_line()` (or "unavailable; don't guess it"): Javid had invented "sunny, 28°C in India" in a greeting. "weather/forecast" left the web-search group.
- `timers.py` — `set_timer(duration | at+day, label)` and `timers(list|cancel)`; `timers.json`. Durations and clock times are parsed here (`parse_duration`: "1h30m", "half an hour", "১০ মিনিট"; `parse_at`: "7" = the next 7 o'clock, a time already past with no day = tomorrow). Each timer carries its announcement in both languages. The page rings them (see Frontend); the CLI rings them from `_ring_timers`. A reminder with no time is still a task.
- `calc.py` — `calculate(expression)`: an AST walk (no eval) over Mahadi's words ("17.5% of 2,340", "2400 + 15%", "square root of 81") and unit conversions (length, mass incl. maund/seer/tola, volume, speed, area incl. Bangladesh's decimal/katha/bigha = 435.6/720/14,400 sq ft, data, time, temperature).
- `markets.py` — `market_price(symbols)`: crypto from Binance's public market-data API (`data-api.binance.vision`, spot 24h tickers; an unknown pair is a 400), stocks/indices from Yahoo Finance's chart endpoint (browser User-Agent; unknown = 404). Names map to symbols ("bitcoin" → BTCUSDT, "nvidia" → NVDA, "s&p 500" → ^GSPC); an unknown word tries Binance, then Yahoo. Results are `web_tools.note_data` (trusted): in a web-backed answer those figures count as confirmed, an older figure in a news snippet doesn't contradict them, and naming Binance counts as citing a source.

### Agents (`agents.py`, `agents/<name>/AGENT.md`)
Specialists with their own LLM loop for jobs too big for one turn. Same frontmatter layout as a skill (parsed by `skills._parse`), plus metadata `max-rounds`, `limits` ("web_search=4 read_page=2"), `prefetch`, `must-show`; the body is the agent's system prompt. `delegate(agent, task)` runs it with a fresh context (prompt + memory block, then the `[Context]` note and the task; no chat history), only its own tools (a call to any other gets one retry with a note), its own round budget, and SPOKEN/SCREEN output. Checks in code: a missing SCREEN part gets one follow-up request; `prefetch` tools are called before the first request with the task's day (`_task_day`) and their results come with the task (gpt-oss-20b called one tool per round and ran out of rounds); `must-show` = every event line of that prefetched result, and the planned day's weekday, must appear in the answer, else one rewrite (the plan once left out both of tomorrow's events and was headed with today's date); web answers get `check_reply` → one rewrite → screen lines with an unconfirmed figure dropped. `[n]` citation marks are removed from the spoken part. The agent's tool calls go through `javid.TOOL_MAP` (so `regression.py`'s spies see them) and count for the turn's required tools (`agents.tools_used()`).
- `research` (required; "research", "deep dive", "investigate", "pros and cons"): 2–4 `web_search` + up to 2 `read_page` → cited report on screen, ≤40 s spoken.
- `planner` (required; "plan my day/tomorrow", "give me a plan for tomorrow" — that one used to miss and the model invented a plan, 2026-10-19 — "organize my week", "what should I do first"; not "a study plan for the weekend"): prefetches `list_events`, `find_free_time`, `list_tasks`, `get_weather` → time-blocked day on screen; suggests only, then asks whether to add the blocks: the next turn gets the agent's `follow-up-tools` (`add_event`) and the plan (the previous reply's screen part rides along for one request, `SCREEN_CHARS`). One request when the plan is complete.

### Exchange rates and market briefs, answered in code (`rates.py`, `markets.py`; 2026-10-20)
Both used to go through the model (the exchange-rates skill, the market agent), which only copied fixed figures into sentences — and credited the koruna-to-taka cross rate to the ECB alone, when its taka half is ExchangeRate-API's. Now `think_stream` asks `_code_answer(user_text)` right after `about.answer`: `rates.request` / `markets.brief_request` parse the message, and `rates.answer` / `markets.brief` (generators: their `tool` events go to the page through `_relay`, which also says "Searching…" before a news search) return the spoken and screen parts in English or Bangla, with no LLM request (an exception in one hands the turn to the model). A message they can't answer whole is left to the model, which still has `exchange_rates` and `market_price` (a `TOOL_GROUPS` entry each, and `REQUIRED_TOOLS` entries for `rates.ASK` / `markets.BRIEF_ASK`): another currency (euro, gold…) or another request in the same message (`_ELSE` in each module: weather, a timer, the price in taka…). A plain coin or stock price question ("what's the bitcoin price?", `_MARKET_ASK`) still goes to the model with `market_price`.
- **Rates** (`rates.ASK`: "exchange rates", "currencies" but not "crypto currencies", yuan, koruna, Bengali ইউয়ান/কোরুনা/এক্সচেঞ্জ রেট): CNY/CZK per USD from the ECB reference rates (official, via api.frankfurter.dev), BDT from ExchangeRate-API (open.er-api.com, aggregator; the ECB has no taka), 15-min cache, `certifi` for HTTPS (python.org macOS builds have no CA bundle for urllib). `_mentions` finds the currencies named and an amount ("500 yuan", "one koruna", "$50", Bengali digits): two currencies = that pair (the one with the amount is the "from"), one non-USD currency = in taka, otherwise the board. Cross rates and conversions are computed here; the spoken part gives two decimals and names each figure's source and date (`_credit`), the screen keeps the published precision. A lone "dollar to taka" question still goes to `web_search` (Bangladesh Bank publishes the official rate).
- **Market briefs** (`markets.BRIEF_ASK`: "crypto/stock market", "market update", "how's bitcoin", "my coins"…, never a news request; Bengali ক্রিপ্টো মার্কেট/শেয়ার বাজার): `symbols_in` finds the coins and stocks named (known names; tickers like FOOCOIN; names that are English words — near, link, dot — only in capitals), else BTC/ETH/BNB/SOL, or the S&P 500/Nasdaq/Dow for "the stock market". `quotes()` (structured; `market_price` formats the same data for the model) → one `news_headlines` search (crypto market, the companies, or the stock market; ≤2 topics, per_topic 2) → spoken: up to 4 assets with their moves, the first headline, "I couldn't find X" (unknown) or "couldn't get prices" (a fetch failed), and "I don't give buy or sell advice" when asked whether to buy; screen: prices by source, news, "Not financial advice." A headline whose figure only one news site gives (`web_tools.check_reply`) is left out; there are no predictions.

### News, answered in code (`gnews.py`, `news.py`; 2026-10-24)
News is what Mahadi asks for most, and through Tavily + the model it went wrong in his own chats (2026-10-20/22): TV listings from unknown sites read out as world news, "Can you show me the news briefing of today?" answered with his empty task list, a digest replaced by "I couldn't confirm a specific growth figure", "I couldn't reach the news sites" during a Tavily ConnectionError, and "why not just go to Google?" three times in one evening.
- **`gnews.py`** reads Google News' public RSS (no key, no credits, ~0.5–1 s a feed, cached `CACHE_SEC` = 10 min): editors' sections (`WORLD`, `BUSINESS`, `TECHNOLOGY`, `SPORTS`…) and searches with `when:2d` and a `site:` list of established outlets per kind of story (`WORLD_SITES`, `BD_SITES`, `TECH_SITES`, `BIZ_SITES`, `CRYPTO_SITES`, `SPORT_SITES`). `TOPICS` maps each topic (world, bangladesh, asia, europe, middle east, africa, americas, usa, war, ai, tech, business, markets, crypto, sport, cricket, football, science, health, entertainment, climate, plus `COUNTRIES`) to its English feed and its Bangla one; `ALIASES` are the words for each in English and Bengali (a Bengali word is matched with its case ending: বিশ্বের); `key_for` maps the model's topic words ("crypto market") to a key. A region or country first takes the world section's stories that mention it (editor-ranked), then its search. Filters (`is_junk`): section/video/podcast/opinion/listicle titles, "Label | …" prefixes, market clickbait, under 4 words, older than `MAX_AGE_HOURS` (48); at most `PER_OUTLET` per outlet; the same story under two topics stays under the first (`same_story`). Bangla mode reads the Bangladesh edition in Bengali minus West Bengal's papers (`_INDIAN_BENGALI`, `.in`). An item's `cluster` is the other outlets Google grouped with it ("5 outlets" on screen). Links are Google's redirects; `source`/`domain` are the outlet's. `regression.py` swaps `_get` for `FakeGoogleNews`.
- **`web_tools.headline_items(topics, per_topic, days, lang)`** is the one place headlines come from (the tool `news_headlines`, `markets.brief`, `news.answer`): Google News first, a Tavily news search (a credit) only for a topic Google couldn't give, all registered as this turn's sources (`_add_news_item`: `via: "Google News"`; the outlet's and the cluster's titles go into the figure checks, so a figure two outlets' headlines give counts as confirmed).
- **`news.request(text)`** takes a message only if it is all news request: a news word (news/headlines/top stories/খবর/সংবাদ), topics from `gnews.ALIASES`, a count ("10 news", "three from Asia and three from Europe" = 6: numbers that each go with a topic add up, otherwise the largest counts), and filler words (`_FILLER`: "go to the Google and bring it to me" is filler too). Two topics with no "and" between them name one subject ("Bangladesh cricket team", "AI news from China") and go to the model, unless one is part of the other ("sports news in cricket" = cricket). "From all over the world" is framing, not the World topic, unless nothing else is named; "world" with regions is dropped (the regions are the world). It's left to the model when the message also asks for something else (`_ELSE`: weather, a timer, a task…), asks a question about the news (`_QUESTION`: why, explain, your take, tell me more, that story, "is it open"), says "good news"/"newspaper" (`_NOT_NEWS`), or names something specific (leftover words: "the Dhaka metro rail", "the IVAC holiday": Tavily gives text to answer from). No topic = `DEFAULT_MIX` (en: world, bangladesh, business, ai, sport; bn: bangladesh, world, sport).
- **`news.answer(req, lang)`**: round-robin over the topics up to the count (`_pick`; one topic = `SINGLE_TOPIC` 5, several = `PER_TOPIC` 2 each); spoken: one topic reads up to `SPOKEN_SINGLE` (4) headlines as "Reuters: <headline>.", several read each topic's first as "In Asia, Reuters reports: …"; cut to `SPOKEN_SECONDS` (50) and always ending with what couldn't be fetched and "The full list is on your screen." A headline is quoted as its outlet wrote it (no "Exclusive:", no dotted U.S./U.N., which the page would split as sentences); one whose figure no second outlet gives is shown, not spoken (`_speakable` = `check_reply`). "From Google News" is said when Mahadi mentioned Google. Screen: `Headlines · Google News, <time> (N):`, topic headings, `N. headline (outlet, 3 h ago · 5 outlets)`; the links under the reply are exactly the stories shown, in that order (`web_tools.keep_sources`). Measured live (2026-10-24): 0.7–1.5 s for up to six topics, against ~9 s median (p90 16 s) for a web answer through the model.

### Self-check and "where did that come from?" (`selfcheck.py`; 2026-10-24)
On 2026-10-22 Mahadi asked "Can you evaluate the bug problems in your system so that I can fix the problem?" and "What's wrong? Why cannot you listen and answer?": the model can't see Javid's state, so he got "I'm not able to review my own code" and a figure-check fallback about Reuters, while the server log showed fifteen hands-free sentences dropped for having no "Javid". Both kinds of question are now answered from what Javid records, never by the model.
- **Recording** (in memory only, lost on restart): `note_clip(mode, outcome, transcript)` from `/talk` for every clip (answered, ignored = no wake word outside the window, noise, not_caught, ack), `note_tts(ok, kind)` from every edge-tts try, `note_stt_error(kind)` when Whisper fails (`/talk` then answers `PHRASES["stt_failed"]` instead of a 500).
- **`request(text)`** → "diagnose" (`_DIAGNOSE`: what's wrong?, why can't you hear/listen/answer/get the news, you're not listening, self-check, is everything working?, are you okay?, why are you so slow, কী সমস্যা; `_FIX` + about-you words: "evaluate the bugs in your system"), "provenance" (`_PROVENANCE`: where did you get that?, what's your source?, how do you know that?, who said that?, did you get that from Google?, did you make that up?, কোথা থেকে পেলে) or None. Phrases must end their sentence (`_END`), so "what's wrong with the economy?", "the source of the Nile", "who said that the earth is flat" go to the model; "why don't you search Google?" stays about.py's.
- **`diagnose(text, lang)`**: probes in parallel (Groq's model list with a 4 s timeout, free; one Google News feed; `calendar_tools.status()`), then checks Hearing (last 15 min of clips: the ignored ones and the last one's words, transcription failures, or "nothing heard: check the microphone"), Brain (`llm_status()`: who answers, cooldowns, today's quota per model), Voice (edge-tts failures in the last hour, chat time-to-first-audio median), News and web (Google reachable, Tavily's last error and credits), Calendar (needs a fresh sign-in?), Telegram. Spoken: the part asked about first ("hear" → Hearing, "news" → News and web, "slow" → Voice), then up to three problems in plain words with what to do, or "all working"; screen: the ✓/⚠ list and the latency medians. Telegram `/check` sends the same.
- **`provenance(text, lang, previous)`**: from the previous reply's basis (above): its links ("Google News: headlines from Reuters and the BBC, October 24", or "a web search through Tavily: …") and its tools (`_TOOL_SOURCES`: Binance and Yahoo Finance, the ECB, Open-Meteo, your Google Calendar, your task list, the calculator…), the links shown again (`web_tools.restore_sources`). "Did you get that from Google?" gets "Yes…" only if they were Google News links, else "No, not from Google: …". A reply with no tool and no link: "That one didn't come from a search or a tool: it was the language model's own knowledge (gpt-oss-20b), so it isn't checked. Say 'look it up' and I'll search."

### Watches (`watches.py`; 2026-10-24)
Javid keeps an eye on something and speaks up when it happens: "tell me when bitcoin goes above 90,000", "alert me if ETH drops 5%", "let me know when there's news about the IVAC holiday", "tell me when it starts raining", "বিটকয়েন ৯০ হাজার ডলারের উপরে গেলে জানিও". Created, checked and cancelled in code: no LLM request and no Tavily credit, ever (scheduled prompts elsewhere spend a model request per run).
- **`request(text)`**: a trigger (tell/let/notify/alert/ping/remind me, watch, keep an eye on, set an alert, জানিও) plus a condition, and nothing else in the message (`_ELSE`: a timer, a task, a clock time…). Price (`markets.symbols_in`, or Bengali coin names): a level (`_THRESHOLD`: above/over/below/under/hits/crosses + "90k", "$2,500.50", "৯০ হাজার"; "hits" takes the direction from the current price) or a move (`_MOVE`: drops/rises/moves N%). News (`_NEWS`): "news about X" with waiting words ("when", "new", "comes out", এলে) — "tell me if there's any news about X" asks about now and goes to the model. Rain (`_RAIN`: starts raining, if it rains; "tell me if it's raining" is about now). List ("what are you watching?", "my alerts"), cancel ("stop watching bitcoin", "cancel the ethereum alert", "stop watching everything"). "Watch solana" with no level gets a hint with a level near its price; "tell me when the dollar rate goes above 125" gets "I can't watch that yet" (no promise the model would make and not keep); "tell me if bitcoin is up today" is a question for the model.
- **Creating** fetches the current value (so an unknown coin, or a level already passed — "Bitcoin is already above $80,000: it's at $82,152 now" — is said, and nothing is set), the news watch's baseline (the headlines out now; it says the latest), or the weather now. The same watch twice is refused; at most `MAX_ACTIVE` (12). Lifetimes (`LIFETIME`): price 7 days, news 3, rain 1.
- **Checking**: `start()` (server lifespan, CLI `main`) runs `check_due()` every `TICK_SEC` (10 s): prices every `PRICE_SEC` (30; `markets.quote`, which is the turn-free version of `quotes`), news every `NEWS_SEC` (15 min, `gnews.search(fresh=True)`: each story not `same_story` as one seen before, up to `NEWS_ALERTS_MAX` = 5, then the watch ends), rain every `RAIN_SEC` (10 min, `weather.forecast`). A watch that fires becomes `timers.add_alert(label, announce)` — a timers.json item of kind `alert`, due now — so the page rings it (chime, banner, the announcement in Javid's voice through `/speak`), Telegram pushes it with 🔔, and the CLI says it. Price and rain watches end when they fire. `watches.json` keeps them across restarts; a done one stays listed an hour (`KEEP_DONE_SEC`).

### Telegram (`telegram_bot.py`; 2026-10-20)
A bot made with @BotFather (`TELEGRAM_BOT_TOKEN` in `.env`) long-polls the Bot API (`getUpdates`, no public URL or open port; `_hello` deletes a webhook if one was ever set) from a thread the server starts (`telegram_bot.start()` in the lifespan; nothing happens without the token, and a rejected token stops it with one log line). HTTP is `httpx`; the token is part of every API URL, so error text goes through `_safe` and the `httpx`/`httpcore` loggers are pinned to WARNING (they log request URLs at INFO). The security rules are summarized in `SECURITY.md`.
- **Setup from the phone:** the header's "✈ Telegram" link opens `telegram.html` (`GET /telegram`). Its token box (`POST /telegram/token`, `_local_page_only`) checks the token with `getMe` before saving it to `.env` (`javid._write_env`, mode 0600; a rejected token saves nothing) and starts the bot without a restart (`set_token`; a different bot resets the update offset). Then it shows the pairing QR code (`GET /telegram/status`: Host must be localhost:8000; `segno` makes the SVG) of `https://t.me/<bot>?start=<code>`: the phone's camera opens Telegram, Start sends `/start <code>`, and that account is paired.
- **Allowlist:** only the user ids in `TELEGRAM_ALLOWED_IDS` (`.env`) reach Javid. Anyone else — messages, voice notes, button presses, wrong pairing codes — gets **no reply at all**; `_deny` logs the account id, time and kind to `data/telegram_denied.jsonl` (mode 0600, never the content, at most `DENY_LOG_PER_MIN` lines a minute). The owner an earlier version kept in `telegram.json` is moved into the allowlist at start (`_migrate_owner`). Keys and the model order can't be changed from Telegram.
- **Pairing** (only while the allowlist is empty): `start()` makes a one-time 6-digit code (server log, and the page); `/start <code>` (the QR link) or `/pair <code>` from a private chat adds that user to `TELEGRAM_ALLOWED_IDS`. Five wrong codes make a new one; `MAX_PAIR_FAILS` (20) close pairing until restart.
- **Turns:** each owner message is one `think_stream` turn in the bot's own chat (`create_session("Telegram")`, remade if deleted in the sidebar; `/new` starts another), so phone and web context don't mix — memory, tasks, calendar and past-chat search are shared. It runs under `javid.hold_turn()` and reopens the web's open chat afterwards. The reply is plain text (no markdown), cut at 4,000 characters; a skill's or agent's screen part and the source links follow as their own messages. `sendChatAction` shows typing while tools run.
- **Writes wait for a button** (`approvals.py`): `run_turn` passes `think_stream` a `gate`, so `javid.WRITE_TOOLS` (add/complete/delete task, add/move/delete event, `propose_memory`) don't run — the gate is inside `TOOL_MAP`, so agents' calls are gated too. `approvals.propose` binds each to its exact target (the task line, not its number; the event id, found by title words — `calendar_tools.lookup_event`/`describe_*`, with `move_event_id`/`delete_event_id` to act on it, none of them tools; the day and time resolved to a date and HH:MM) and the model is told it waits. The reply is followed by an "Approve this?" message per action with ✅ Approve / ✖ Reject (`act:ok|no:<id>`); a press runs it once (`approvals.take` + `run`, under `hold_turn`) within `APPROVE_SEC` (120 s) on that action's own message; late, repeated or foreign presses do nothing, and `_expire_buttons` (timer loop) marks expired cards. A typed yes doesn't approve anything: `memory_store.answer_from_reply` is skipped on gated turns, and `delete_event(confirm=true)` just makes another card.
- **Untrusted input:** a forwarded message (`forward_origin` and the older `forward_*` fields, `via_bot`) is never a turn: `_forwarded_turn` keeps it in the chat as "[Forwarded message: someone else's words…]" (`FORWARD_TAG`, `javid.record_turn`) with a canned reply — no model request, so nothing in it can act. Forwarded voice notes and files, and all files (document, photo, audio file…; only a recorded `voice` note is transcribed), are not opened. A message with a link (`http(s)://`, `www.`, `t.me/`, a `text_link` entity) gets `blocked` = the web tools and `delegate` (`think_stream(blocked=…)` filters each round's tools and refuses the call without running or showing it). `propose_memory` is refused when the message has a link, the text holds one, or a forwarded message is among the last `HISTORY_TURNS` turns or this turn's tool results (`_forward_in_view`).
- **Rate limit and lock:** at most `RATE_PER_MIN` (20) messages and presses a minute (`_over_limit`; one "slow down" notice a minute). `/lock` (exempt from the limit) sets `locked` in `telegram.json`, drops pending approvals and stops reminder pushes; while locked every message gets one "locked" notice a minute and presses do nothing. Only the Mac's `/telegram` page unlocks it (`POST /telegram/lock`, `_local_page_only`).
- **No keys or ids out:** `send`, `_edit`, `_answer` and the voice note all go through `_scrub`: `javid._redact` plus bot-token/Tavily/Google-secret shapes, the allowed ids, the chat id and the bot's id, passport-style numbers and 9+ digit runs outside links (a phone number right after phone/mobile/call stays).
- **Voice:** a voice message is downloaded (`getFile`), transcribed with `transcribe_turn` (OGG goes to Whisper as is; audio files aren't), echoed back (🎙 "…"), answered, and the reply also comes as a voice note: `_speech` synthesizes it sentence by sentence as the page does (consecutive sentences in the same `voice_for` voice in one `synthesize` call; the MP3s concatenate), and ffmpeg turns it into OGG/Opus 32 kbps (`sendVoice`); without ffmpeg it's an MP3 `sendAudio`. If edge-tts fails, a "🔇 Voice unavailable" line — never another voice. `/voice` switches between voice notes only for voice messages and for every reply.
- **Timers:** `telegram-timers` checks every 5 s and pushes each due timer once (`timers.take_due_for("telegram")`, "(missed: …)" if it's more than 2 min late), whether or not a page rang it (not while locked); at start, ones that already rang are marked sent without being pushed.
- **Commands** (registered with `setMyCommands`): `/help`, `/new`, `/tasks`, `/timers`, `/lang en|bn`, `/voice`, `/status` (`javid.next_model()` and the providers that are on: no network), `/watches` (what Javid is watching), `/check` (the self-check, `selfcheck.diagnose`), `/lock` — answered in code, no LLM request.
- **Watches:** a watch that fires is pushed like a reminder (`push_due`), as "🔔 …" instead of "⏰ …"; one set from the phone ("tell me when bitcoin goes above 90,000") is answered in code like on the page.
- **One turn at a time:** `javid.hold_turn()` (`TURN_LOCK`, a plain Lock: a web reply is a generator the server may resume on another thread; a holder that never lets go is waited out for `TURN_WAIT_SEC`, then ignored) wraps every turn — `_reply_stream` for `/type` and `/talk`, Telegram's `run_turn` — and the routes that switch or clear the open chat (`/reset`, new/open/delete chat). `_use_session` only checks the chat exists; the turn opens it under the lock. Before Telegram, two tabs could already interleave turns. `_reply_stream` is an async generator: the turn runs in its own thread, which holds the lock and hands events over an `asyncio.Queue`; when the page hangs up (Stop, barge-in) the generator's `finally` sets `hung_up`, and the thread closes `think_stream` at its next event (its `finally` still logs what was said) and lets go. Holding the lock inside a sync generator the server resumed kept it after a hang-up until `TURN_WAIT_SEC` ran out (measured: the next message waited the full 120 s).
- Tested offline with `regression.FakeTelegram` (`telegram:` cases, `Case.drive`): setup from the page (token checks, `.env` in scratch, QR link, `/start <code>` filling the allowlist), pairing, strangers' silence and the denied log, the separate chat, a voice message (fake transcript, fake edge-tts, ffmpeg skipped), Approve for memory and for a task after the list shifted, an expired button / typed yes / Reject, a forwarded "delete all events", a link, the rate limit and `/lock`, the reply scrub, webhook removal and the owner migration, timer pushes, the commands.

### Chats (sessions)
Like Claude's sidebar, on the right: each chat is a separate conversation. `messages` only ever holds the open chat (`open_session` reloads its last `CONTEXT_TURNS` messages), so Javid's context and the 6-turn window never mix chats; `search_history` deliberately searches all of them. The page sends its open chat's id with every `/type` and `/talk` (`_use_session`), so two tabs can't cross-post. Titles come from the first message (`auto_title`, no LLM request); double-click renames (`named` stops auto-titling). "+ New" reuses the open chat if nothing was said in it; empty chats aren't listed unless open. Delete removes the chat's lines from chat_log for good (two clicks; the FTS index rebuilds because the log shrank). Search = title substring + FTS match on message text (`memory_store.search_sessions`, all words, prefix).
- `_restore_context()` runs at **startup only** (server lifespan, CLI `main`), never on import — importing javid from a script or the suite must not touch the real chats. It first splits a v1 log (no `session` fields, "divider" lines between conversations) into chats, once, keeping `chat_log.jsonl.bak-<time>`.
- `current_session()` creates a chat lazily without clearing `messages` (clearing there wiped the message being answered); `new_session()` is the explicit "+ New" and does clear.
- Routes: `GET /sessions?q=`, `POST /sessions`, `POST /sessions/{id}/open`, `PATCH /sessions/{id}` (title/pinned), `DELETE /sessions/{id}`; `/history?session=`.

### Memory v2 (`memory_store.py`)
- **Javid never writes memory.** The only tool is `propose_memory(text, file)` (`user` → USER.md facts, `memory` → MEMORY.md lessons/preferences); it creates a *pending* proposal and the page shows an Approve / Edit / Reject card (`memory_proposal` event, also listed in the sidebar). It is saved by the card (`POST /memory/proposals/{id}/approve|reject`, behind `_local_page_only`), or by a plain yes/no on the **very next** message, decided in code (`answer_from_reply`, at the top of `think_stream`, no LLM request) — the same pattern as `delete_event`. There is no recall/clear tool: the files are already in the prompt, and deleting is done in the sidebar.
- **Secrets are refused in code** on every path (propose, approve, sidebar edit): `secret_reason()` — password/PIN/key/token/passport/NID/card words, provider key shapes, passport-style and long digit runs (a phone number next to "phone/mobile/call" is allowed).
- **Required tools** (`REQUIRED_TOOLS` in javid.py): "remember that…" must end in `propose_memory` and "what did I say about…" in `search_history`, and an explicit "look it up"/"search online"/"google it" in `web_search` (`_WEB_ASK`; not for the user's own calendar/tasks/chats, a task or reminder, or a required-skill turn — K2 answered "look up how tall Everest is" from memory); a weather question in `get_weather` (`_WEATHER_ASK`), "set a timer"/"remind me at 7"/"in 20 minutes" in `set_timer` (`_TIMER_ASK`), a bare sum or conversion in `calculate` (`_CALC_ASK`, a class: the whole message must be maths, so "open 24/7" or a date isn't), a coin/stock price in `market_price` (`_MARKET_ASK`, which also drops the web tools for that turn), and a required agent's triggers in `delegate`; a reply without it gets one retry with a note (Qwen answered "Got it, I'll remember" and saved nothing). "Remember to X" is a task, not memory.
- **Pushback re-check** (`_CHALLENGE`): "how come?", "are you sure?", "I thought…", "that's wrong"… after a turn that used a `RECHECK_TOOLS` tool adds that tool to the turn's required tools, so the model must call it again before answering (gpt-oss-120b otherwise just agreed, "I misspoke", without checking).
- **Past chats:** `search_history(query)` = SQLite FTS5 over `chat_log.jsonl` (`chat_index.db`, synced incrementally by line count, rebuilt if the log shrinks), stop-words dropped, prefix OR match ranked by bm25, top 5 with dates.

### Calendar edit tools (`move_event`, `delete_event`)
Events are found by title words in Python (`_find_events`/`_pick`), never by model-supplied IDs; zero or several matches are reported back, not guessed. The model often fills optional `day`/`time` with an invented "today", so a hint that matches nothing falls back to a title-only search. `delete_event` is two-step **and enforced in code**: the first call only describes the event; deletion is accepted only if `confirm=true` arrives on the *next* user message (`calendar_tools._turn`, bumped by `think_stream` via `new_turn()`). Don't weaken this to a prompt instruction — the model ignores those.

### Providers, budgets and privacy (`providers.py`, `config/providers.yaml`; 2026-10-25)
Every outside service with a key or an allowance is one entry in `config/providers.yaml` (tracked): `name`, `label`, `kind` (llm / search / extract / rerank / tts / storage), `env` (one variable, or a list: Cloudflare needs an account id and a token), `enabled`, `priority`, `allowance` (the free allowance in the provider's **own unit**, never converted to tokens: `amount`, `unit`, `per`, `per_model`, `verified: false` for the seeded ones; `from: headers` for Groq, `from: api` for ElevenLabs; `amount: 0` = no free tier, so off; `null` = not published), `reset` (daily_utc, daily_pacific, monthly_utc, rolling_24h, headers, api), `rate_limit` (OpenRouter's 20 a minute), `costs` (a call's price in that unit when the response doesn't say), `timeout_ms`, `personal_ok` (default false; Mahadi's to set, see the rules at the top). The file is read again when it changes (every `RELOAD_SEC`); a broken file keeps the last good registry and shows the problem on the panel. Seeded 2026-10-25: groq, gemini, openrouter, cloudflare, deepseek (paid only: `enabled: false`, `amount: 0`), ifm (allowance not published), tavily, exa, brave, firecrawl, cohere, elevenlabs. Only groq, gemini, deepseek, ifm (the model chain), tavily (web search) and elevenlabs (its balance only — the voice stays edge-tts) are used by code; the rest are registry entries, `--live` smoke calls and panel cards until each is wired into a feature, which must ask `providers.allow` before a call, `providers.record` it after, cool down with `providers.cooldown_seconds`, and respect `personal_ok`.
- **On** = `enabled` and every variable in `env` set (`providers.is_on`). The server and CLI print `providers.startup_line()` at start: names only, never a value.
- **Usage ledger** (`data/providers.db`, SQLite, mode 0600): one row per call — provider, model, op, units in the provider's unit, latency, status (ok, cached, aborted, rate_limited, quota, payment, auth, missing, unavailable, error, refused) and a short detail (an exception's class name, never a query, a key or personal data). Written by the model router (`chat`; the units: tokens for Groq, one request for per-request allowances), `ping_models` (`ping`), model listings (`models`), key checks (`verify`), Whisper (`stt`), Tavily (`search`, `extract`, `cached`, `refused`), ElevenLabs (`balance`) and `--live` (`smoke`). Usage = the sum of units since the start of the provider's reset window (`window_start`/`next_reset`), so counters start again with their window; no job resets them. A new ledger imports `llm_usage.jsonl` (last 35 days) and `tavily_usage.jsonl` once (`IMPORT_FILES`). A failed ledger write is printed and dropped, never the answer.
- **Budget guard** (`providers.state`, `allow`, `ordered`): ready → reserve at `RESERVE_AT` (80%: used only when the others fail) → off at `OFF_AT` (95%) until the next reset; a call whose known cost would go past the allowance is refused even below 95% (Exa at $9.40 of $10 with a $0.70 call); `amount: 0` keeps a provider off; an unknown allowance (`null`) is counted but only the provider's own 402/429 stop it. Groq's per-model numbers come from `javid._groq_usage` (set as its reporter) and ElevenLabs' character balance from `GET /v1/user/subscription` (`refresh_balance`, every `BALANCE_SEC`, in the background; the key only in the request's header).
- **Cooldowns** (`cool`, `cooldown`, `clear_cooldown`; table `cooldowns`): per provider, or per model for `per_model` providers; a longer one already running stays. `error_kind` names an error: 429 → rate_limited, 402 → payment, a quota/plan-limit message (Tavily's 432/433 arrive as `ForbiddenError`) → quota, 401/403 → auth, 404 → missing, 5xx/network/timeout → unavailable.
- **Privacy rule** (in the model router and the web search, 2026-10-25): calendar, memory, chat history and tasks go only to providers with `personal_ok: true`.
  - `_request_messages` tags what it builds: the system message's `_public` text is the static prompt without the memory block, the user message's `_public` is the `[Context]` note without the older-chat summary and the carried calendar facts, and the history and earlier drafts are `_personal` (dropped). `_open_stream` sends a provider without `personal_ok` that version (`_public_request`), without the `PERSONAL_TOOLS`; `_messages_for` strips every `_` tag before anything leaves Javid.
  - A request tagged `_needs_personal` goes only to providers with `personal_ok` (`_models_to_try(personal=True)`); with none in the chain, `PrivacyBlocked` → `PHRASES["no_personal"]` and `NO_PERSONAL_SCREEN`, and nothing is sent. The tag goes on the turn's message when `_turn_needs_personal`: Mahadi's words (`_PERSONAL_ASK`: "my calendar", "am I free", "remind me to", "remember…", "what's my…", "good morning"…, deliberately much narrower than the tool groups, which matched 39 of his 105 real messages — mostly news and weather "today/tomorrow" — against 6), a required personal tool, the planner, or a short follow-up to a turn that used one. It is added during the turn when a personal tool's result comes back, when a skill unlocks one (morning-brief), or when a model reaches for one it wasn't offered (Groq's "not in request" → widening). Agents tag their own requests the same way (`agents.delegate`).
  - A web search query carrying words from a task, a memory line or a calendar/task result in context (two in a row, or a name) isn't sent to a search provider without `personal_ok` (`web_tools._private` with `javid._personal_leak`; words Mahadi used in that message and the system prompt's don't count), and isn't handed to the Google News fallback either. Best effort: chat history isn't checked.
  - Not routed, so not covered: Whisper (every voice clip goes to Groq), edge-tts (every spoken reply goes to Microsoft), Telegram (the bot's chat), and the keyless services (Google News gets topic words, Open-Meteo a place, Binance/Yahoo symbols).
- **Providers panel** (`GET /providers` → `javid.providers_status()`): `providers.status()` (each provider's state and why, used / allowance, reset, rate limit, last call and error, personal data allowed or not) plus `llm_status()` and the next model.

### LLM provider chain (`javid.py`)
- **Order:** `current_chain()` = the user's saved order (`llm_chain.json`, gitignored) else `default_chain()` = `[LLM_MODEL, *LLM_FALLBACKS]`. Entries are bare Groq ids, or `gemini:<model>` / `deepseek:<model>` / `ifm:<model>` (OpenAI-compatible endpoints via the `openai` SDK). `ifm:` is MBZUAI's K2 Horizon API (`api.ifm.ai/v1`, `IFM_MODEL` = `IFM/K2-Horizon-375B-A23B`, the only size it serves). Its model list ignores the key, so `_verify_key` checks an IFM key with an empty chat request instead (401 = bad key, 400/422 = good, no tokens spent). IFM 400s on any follow-up turn unless every assistant message has a thinking field, so `_messages_for` adds `reasoning_content: ""` to them for IFM (an empty one is accepted). Not yet tried live: reasoning depth (`chat_template_kwargs.reasoning_effort`, which the model card says to keep at "high") is left at the server's default. A provider without its key in `.env` is skipped.
- **Routing:** `_open_stream` → `_create` → `_provider_client`, chosen by id prefix; the key's variable comes from `config/providers.yaml` (`_key_env`). A 429, 5xx/network error, 404, 401/403 or DeepSeek's 402 ("insufficient balance") puts that model in a cooldown and the next model answers: `_cool` → `providers.cool`, kept in the ledger's database so a restart respects it. How long is `providers.cooldown_seconds`: a 429 until its retry-after (`explicit_wait` parses the `retry-after` header, Groq's "try again in 7m11s" and Google's "retry in 6h21m37s"; 60 s if it doesn't say), a 402 or a quota error until its retry-after or the allowance's reset, a rejected key or a missing model an hour, an outage 30 s. Only that model rests when its provider's allowances are per model (Groq, Gemini) and the error is the model's (a 429, a 404, a 403, an outage); a 401 or an empty balance rests the whole provider. A 400 is *not* "unavailable" — it propagates to the malformed-tool-call retry.
- **Two SDKs:** the `API_ERRORS`/`RATE_LIMITED`/`UNAVAILABLE`… tuples cover both `groq` and `openai` exception classes. Use them, not the bare class names.
- **Per-model request options** (`_model_kwargs`): only gpt-oss gets `reasoning_effort="low"` (Qwen given `"none"` skipped the tool call and claimed it was done); Gemini gets `reasoning_effort="low"`. `extra_content` on Gemini tool calls must be echoed back and is stripped for other providers (`_messages_for`); Gemini chunks may lack `index`/`id` (handled in `_stream_completion`/`think_stream`).
- **Provider limits measured on this key (2026-10-13):** Gemini `gemini-3.7-flash` (the configured `GEMINI_MODEL`, highest that answered) = 20 requests/day then "retry in 6h"; `gemini-3-flash-preview` = 5 requests/min, ~2 s; `gemini-3.8-flash` 503s; 3.1-pro/4-argon not free; `gemini-2.5-*` 404 (retired). Google retires IDs quickly — check `models.list()` before trusting a name; `llama-3.3-70b-versatile` isn't on the Groq key either. Gemini/DeepSeek are fake-tested plus a partial live run; Gemini is a thin safety net, not a replacement.
- **Providers panel & key management:** `llm_status()` (served at `GET /llm`, and inside `GET /providers`) merges the chain, the budget guard's state per model (serving, ready, reserve, off, cooling, missing, nokey, disabled), `llm_usage.jsonl` (Groq's token counts per request, counted only since logging began), per-minute/per-day headroom from `x-ratelimit-*` headers, and the daily cap — which Groq only reveals inside a 429 message (parsed into `llm_quota.json`; `KNOWN_TPD_LIMITS` seeds it). "Test models" (`POST /llm/ping`) skips a model that is off or resting: a ping is a real request, and a successful one is not capacity. The dialog can reorder/add/remove models (`PUT /llm/chain`) and paste keys (`PUT/DELETE /llm/key/{provider}` → `set_provider_key`: verified with a token-free `models.list()`, written by `_write_env` which preserves other lines; the key is never returned, only a 4-char hint; `.env` is always rewritten mode 0600, and provider error text passes through `_redact` before it is stored, logged or shown, since a provider may echo part of a key). Every mutating `/llm/*` route goes through `_local_page_only` (Host must be localhost:8000 and Origin must match). The Groq key is read-only there.

### `server.py` routes
- `/type` and `/talk` stream **NDJSON events** — `trace` (always first: the latency trace's id), `transcript`, `tool`, `say`, `sources`, `lang` (a message switched the language), `agent` (an agent took the job), `delta`, `error`, `ignored`, `done` (with fresh `tasks`/`memory`/`timers` and the current `lang`) — consumed by `streamReply()` in `index.html`. `_reply_stream` maps each kind explicitly; an unknown kind is dropped (it used to fall through to `delta`, i.e. be spoken).
- `GET /telegram` (the setup page, `telegram.html`), `GET /telegram/status` (set up / running / paired, and while unpaired the code, its `t.me` link and a QR SVG), both for this machine only (Host must be localhost:8000); `POST /telegram/token` (`_local_page_only`) checks and saves the bot token; `POST /telegram/lock` (`_local_page_only`, `{locked}`) is the only way to unlock remote control after `/lock`.
- `GET /providers` (`javid.providers_status()`: every provider in `config/providers.yaml` with its state and why, used / allowance in its own unit, reset time, last error and its models, plus `llm` = `llm_status()` and `next_model`; never a key, only variable names); `GET /agents`; `GET /timers`, `POST /timers/{id}/fired` (→ `{"first"}`: only the first tab announces), `DELETE /timers/{id}` (both behind `_local_page_only`); `GET /watches` (the Watching panel's rows: label, status such as "now $80,772.01", kind), `DELETE /watches/{id}` (`_local_page_only`). The `done` event also carries `watches`.
- `GET/PUT /language` reads/sets the reply language (the header's EN/বাংলা toggle; PUT goes through `_local_page_only`). `/speak` takes `{text}`: the voice comes from the server's language setting, not the page (a page's copy of the language can be stale).
- `/talk` takes `mode`: `push` (always answer), `wake` (hands-free; only if the transcript starts with the wake word, via `strip_wake_word`), `followup` (hands-free, within `FOLLOWUP_MS` of the end of a reply; no wake word needed). In `push` a one-word transcript is treated as a clipped recording ("I didn't catch that") unless it's yes/no, a greeting (`_SMALL_TALK`), or the bare wake word (→ the "Yes?" ack).
- `/speak` returns neural TTS audio for one sentence; 503 on failure. Sidebar REST routes (`/tasks`, `/memory`, `/calendar`, `/history`, `/reset`) edit data directly without the LLM. Startup threads regenerate the fixed phrases' audio (`warm_phrases`) and ping every model.

### Latency tracing (`tracing.py`, see `ARCHITECTURE.md`)
Observation only — it must never change what Javid does. `/talk` and `/type` open a `tracing.Trace` (hands-free clips the server ignores aren't traced); `server._traced` wraps the reply stream (first event `trace` with its id, `reply_out` on the first delta, `tracing.finish` at the end); `javid.py` marks `routing_done`, every LLM request (`_stream_completion`: start, first chunk, end, model) and every tool call on the module's *current* trace — a global, one turn at a time like `messages`, and every call is a no-op with no trace active (regression.py, scripts, the greeting). The page adds end of speech, first text, first `/speak` request, first audio, first answer audio and audio done (`traceNew`/`traceMark`/`traceEnd` in `index.html`) with `POST /latency/{id}` (`_local_page_only`) once speech ends or is stopped/interrupted; a trace the page never reports is written after `CLIENT_WAIT_SEC` as `no_client`. Lines go to `data/traces.jsonl` as ms offsets from t0 (end of speech; Send for typed). Types: `web` (a web tool ran), `command` (another tool ran, or the reply was decided in code), `chat`. `GET /latency` = last 20 + per-type median/p90 time to first audio over the last `STATS_WINDOW` (200); the sidebar's Latency card and dialog show them. The CLI traces its turns too (`source: "cli"`). `regression.py` points `TRACES_FILE` at scratch (before 2026-10-24 its offline Telegram cases wrote 104 fake `telegram` traces into the real log, 2026-10-20 to 10-22; they're still in `data/traces.jsonl`, labelled with the suite's test messages: "Tell me a fun fact.", "Remember that my sister's name is Nadia."…).

### Frontend (`index.html`)
- **Speech:** replies are split into sentences as they stream (`feedSpeech` — boundary is `.!?` or the Bangla `।` + whitespace, so "27.3" doesn't split); each sentence is fetched from `/speak` immediately and played in order (`speechQueue`/`playNext`); `speechGen` invalidates stale callbacks after Stop.
- **Hands-free:** an AudioWorklet taps the mic; `onFrame` runs an energy VAD (adaptive noise floor, pre-roll, thresholds in `VAD`) and encodes 16 kHz WAV. Listening pauses while `javidIsBusy()` so Javid never hears himself. **Conversation mode:** "Javid" starts a conversation; after each reply (or the "Yes?" ack) the follow-up window (`FOLLOWUP_MS`, 30 s, orb "Go ahead…") lets the next question come without the name, and each reply reopens it. It was 8 s until 2026-10-22: Mahadi's next question usually came after it closed and the server dropped it as a `wake` clip without the name (15 in one evening, seen only as `[hands-free] ignored:` lines in the server log; ignored clips aren't traced). The cost is that speech nearby (TV, other people) within 30 s of a reply can be answered.
- **Barge-in** (hands-free only, where the mic is already open): while Javid speaks, `onFrame` runs `bargeStep` instead of ignoring the mic. It compares the mic level with the playback level (`tapPlayback`: `audio.captureStream()` → analyser, never to the speakers): threshold = max(`BARGE.minRms`, noise × 4, learned echo ratio `echoK` × playback × 3); `echoK` is learned only on echo-only frames with Javid clearly audible. Trigger = `BARGE.holdMs` (250 ms) of speech, allowing 3-frame syllable gaps; the first 300 ms of each sentence are ignored while echo cancellation settles. `bargeIn()` stops current + queued speech and the stream (`stopAll`), marks the reply "⏸ interrupted" (text kept), and starts a follow-up capture from the pre-roll. Each trigger is logged to the console and `POST /bargein/log` → `bargein_log.jsonl` with its levels and outcome (`speech`, or `false` when the clip was too short or the server ignored it as noise) — check that file after a speakers test. Measured on synthetic levels from real TTS clips (2026-10-14): never self-triggered with echo leak up to 0.6, coughs ignored, normal speech detected 235–277 ms after onset; a lone "Stop." (~250 ms voiced) is too short by design — Esc/Stop/push-to-talk still interrupt instantly. Both mics (hands-free and push-to-talk) use `echoCancellation` + `noiseSuppression`.
- **Timers:** the sidebar's Timers panel (hidden when empty) counts down each second; a due timer rings once per tab set (`rungTimers`): `POST /timers/{id}/fired`, and if this tab is first, the alarm banner, a WebAudio chime (a sound, not a voice) and then the timer's announcement through `/speak` (Javid's own voice, queued behind anything he's saying). Synced from the `done` event, on load and every 10 s (a watch's alert is due at once). Browsers block audio until the page has been clicked once; the banner still shows.
- **Watching panel** (hidden when empty, under Timers): `GET /watches` on load, every 15 s and from the `done` event; each row is an icon (↗ price, ◉ news, ☂ rain), the label ("Bitcoin above $90,000"), its status ("now $80,772.01", "nothing new yet") and ✕ (`DELETE /watches/{id}`). It reuses the timer rows' classes (Overdrive styles them too).
- **Themes:** **Aurora** (default; `localStorage` value `classic`): midnight glass panels, slow-drifting violet/cyan light (`body::before`), an iridescent orb (a blurred conic gradient turning inside the sphere, `--o1..3`/`--swirl` per state, a halo `.orb-aura` placed after the rings so `.orb-ring:nth-child(2/3)` still match), Inter/Sora/JetBrains Mono from Google Fonts; colours are tokens on `:root`. Or **Overdrive** (the ⚡ button): black and red, chamfered panels and buttons, scanlines, a glitching title, the orb as a reactor core with counter-rotating rings whose speed follows the state (`:has()`), its own orb labels (`OD_LABELS`) and Chakra Petch. Every Overdrive rule is scoped to `html[data-theme="overdrive"]`; a block at its end switches off Aurora-only decorations (halo, swirl, glass blur, pill shapes) — add to it when Aurora gets a new decoration. The `<script id="theme-boot">` in `<head>` applies the saved theme before the first paint; `updatePlaceholder()` picks the composer hint from theme and language. `prefers-reduced-motion` stops the animations.
- **Screen parts** go through `renderScreen()`: each line is escaped, then headings (a short line ending in ":"), bullets, numbered items, time blocks ("9:00 AM - 9:30 AM  Call mom (suggested)" → a timeline row with a tag), green/red percentage moves (+, −, – or "up/down x%") and `[n]` citation badges. Sources are numbered chips. The header pill shows the model that answers next (from the Providers panel). Quick-action chips above the composer send ready-made requests through `submitText` and are disabled while Javid is busy.
- **Providers panel** (left sidebar, "Details" opens the dialog; it was the Models panel until 2026-10-25): a row per provider that is on (its state's dot; used / allowance in its own unit, 🛡 reserve, ⛔ off with its share, ⏳ resting, or for Groq the serving model's daily tokens) and a "Not on" line; the dialog has a card per provider grouped by kind (state and why, a meter of the free allowance marked "unverified" when it is, the reset time, what Javid uses it for, personal data allowed or never sent, last call, last problem), then the model cards in chain order with their controls, then the chain and key controls. Refreshed every 10 s from `GET /providers`; the countdowns tick locally.

## Conventions driven by model quirks (gpt-oss-20b on Groq)

- **It miscounts and gets weekdays wrong.** Do counting and date math in Python and put the answer in the tool result: `list_tasks` leads with "N pending, M done"; calendar tools accept the user's words (`"friday"`, `"3pm"`) and resolve them in `_parse_day`/`_parse_time`; `list_holidays` computes long breaks itself.
- **It guesses when data is thin** (and invents figures, e.g. an inflation rate no source gave, which is why `check_reply` exists). Holidays come from Google's public holiday calendars (`en.<code>#holiday@group.v.calendar.google.com`), not web search. Even with `list_holidays`' result in hand it added days ("holidays run from Sunday, October 18" when the list starts on the 20th), so replies are checked in code: `calendar_tools.check_holiday_reply` flags a date in a clause about a holiday/closure (every non-negated clause when the turn is about holidays) that isn't in a `list_holidays` result from this or the last 3 turns, or in this turn's web results (an office's own notice may close more days); long-break ranges count day by day. One rewrite (`holiday_correction`), then the tool's own list (`holiday_fallback`; Bangla gets `PHRASES["holiday_unsure"]`). Whether a particular office or visa centre (IVAC) is open is that office's notice, not the national list: `list_holidays`' description says to search, and "official/open/closed/visa/IVAC" trigger the web tools. `transcribe` rewrites Whisper's "IVEC/IVEX/IBEX center" to IVAC (`_IVAC`). Home country is Bangladesh (`HOME_COUNTRY`, Friday–Saturday weekend `HOME_WEEKEND`).
- Replies are spoken: the prompt demands 1–3 short sentences, no markdown or lists.

## Speech (voice is permanent — see top)

- `synthesize(text, lang)` is the only TTS path — the page's replies, `say` phrases, greeting and timer announcements (all via `/speak`), the warm-up and the CLI's `speak`: edge-tts, MP3, voice from `voice_for()` — `VOICES[lang]` (`lang` = the server's setting; only the warm-up names one), and Bengali letters always get `EDGE_VOICE_BN` (AndrewNeural turns Bengali into a near-silent clip; that plus the page skipping chunks without `[a-z0-9]` is why the first Bangla reply was silent). Letters, `_BN_LETTERS`, not the whole Bengali block: the taka sign `৳` and Bengali digits are in it, and "৳122.50" in an English reply would have switched that sentence to Pradeep (Andrew reads `৳` fine). The cache is keyed by (voice, text). The `voice:` cases in `regression.py` speak replies through `/speak` as the page does, with a fake edge-tts that records the voice of every sentence and fails on any rate/pitch option. The `TTS_ENGINE` switch, Groq Orpheus, `LOCAL_FALLBACK` and `_say_wav` were removed on 2026-10-14 so nothing can swap the voice.
- edge-tts is an unofficial endpoint and erratic (normally ~1 s, but 3–5 s stalls and `NoAudioReceived` streaks; roughly half of calls failed during one test). `synthesize` gives a try `EDGE_FIRST_SEC` (6, 8, 10 s on tries 1–3) for its first chunk and then `EDGE_STALL_SEC` (4 s) between chunks, so a slow sentence that is still arriving is kept and only a stalled one is retried (until 2026-10-24 a fixed 6 s for the whole sentence threw slow ones away: during a slow spell every try of a news answer timed out). Up to `EDGE_ATTEMPTS` (3) tries, then it raises (`/speak` returns 503). At most `EDGE_PARALLEL` (3) syntheses run at once (`_edge_slots`, taken before a try's clock starts): a news answer is 6–10 sentences and the page asks for them all together, and ten at once took up to 4.7 s each. The user prefers the natural voice over speed. Parallel/hedged edge-tts requests for the *same* sentence made it slower — don't add them back. A `WSServerHandshakeError` **403** on every try (not the occasional stall) means Microsoft changed what the endpoint accepts: upgrade `edge-tts` (2026-10-14: 7.2.8 got 403s, 7.3.1 fixed it, same voice). Check the clock too, since the auth token is time-based.
- The page has **no browser-speech fallback** (it was removed after it made the voice "change" during an edge-tts outage). A `/speak` 503 means the server already made `EDGE_ATTEMPTS` (3) tries: `playNext` skips the sentence, `voiceUnavailable()` puts a "🔇 Voice unavailable" note under that reply and shows a toast at most once a minute. Never fail silently. A running server keeps the edge-tts it started with: after upgrading the library, restart the server.
- The fixed phrases (`PHRASES`, both languages) are regenerated at startup, sentence by sentence as the page asks for them (`warm_phrases`, "Yes?" and "Searching…" first); the cache is in memory only, so a restart regenerates it.
- **Wake word:** variants and Whisper noise phrases are `_WAKE`/`_NOISE`; `_WAKE` is deliberately phonetic (`_NAME`) because without a hint Whisper spells the name many ways. Hands-free clips are transcribed with `bias_name=False`: the `prompt="Javid"` hint makes Whisper answer silence/noise with "Javid", which the matcher accepts (spurious "Yes?"). Keep the hint for push-to-talk only. In Bangla mode the hint is `জাভেদ` (a Latin "Javid" made Whisper romanize words) and `_NAME_BN` matches the Bengali-script spellings (জাভেদ, জাবিদ, জাবদ…).

## Bangla mode (reply language)
- The language lives in `language.json` (`get_language`/`set_language`) and is re-read every turn — **enforced in code, never left to the model's memory** (the original bug: it replied once in Bangla, then drifted back to English).
- `think_stream` checks `language_switch()` first: "let's speak Bangla", "Bangla te kotha bolo" (English Whisper writes it as e.g. "Bangla T. Cotabioello", hence the loose `_KOTHA`), "বাংলায় কথা বলো", "speak English", "স্পিক ইংলিশ", misheard "ইন্রেসি ত্সা পালো"… A bare switch gets the canned `PHRASES["switched"]` with no LLM request; with a question attached the question is answered in the new language.
- The language goes into the `[Context]` note each turn (plus Bangla day words: কাল = tomorrow) and the static prompt says "reply in the current language, at most 2 spoken sentences". A reply in the wrong script (`wrong_language`) gets one rewrite, like the web check (`notes` in `think_stream`).
- STT: `transcribe` passes the language to Whisper. `transcribe_turn` (used by `/talk` and the CLI) gives short Bangla-mode clips a second English pass, used only if it's the switch to English or a bare wake word — Bangla Whisper turns English "speak English"/"Hey Javid" into noise.
- `calendar_tools._parse_day` understands আজ/কাল/আগামীকাল/পরশু and Bengali weekdays; `TOOL_GROUPS` have Bengali trigger words. `is_noise` keeps Bengali letters (it used to strip them, so every Bangla request looked like noise).

## Testing safely

When exercising the agent from your own scripts (not `regression.py`, which does this already): point `javid.HISTORY_FILE`, `SESSIONS_FILE`, `TASKS_FILE` and `memory_store.MEMORY_DIR`/`HISTORY_FILE`/`INDEX_FILE`/`LEGACY_FILE` at temp files (set `memory_store.HISTORY_FILE` *after* redirecting `javid.HISTORY_FILE`), never call `add_event` against the real calendar — replace `calendar_tools._service` with a fake — set `web_tools._client` to a fake (e.g. `regression.FakeTavily()`; importing `regression` points the usage ledger at scratch but not the client, so a real search spends credits the Providers panel never sees), set `timers.TIMERS_FILE` and `watches.WATCHES_FILE` to temp paths (and never call `watches.start()` from a script: its thread would check and ring), set `gnews._get` to a fake (`regression.FakeGoogleNews().get`) when the headlines must be fixed, replace `weather._get_json`/`markets._get_json` with fakes (`regression.fake_weather_get`/`fake_market_get`) if the result must be fixed, for anything touching `.env` set `javid.ENV_FILE` to a temp path and use fake keys, and set `providers.DB_FILE` to a temp path with `providers.IMPORT_FILES = {}` (a script's calls must not count against the real allowances or cool down the real providers) and `providers.REGISTRY_FILE` to a scratch copy to change any flag. A test server (`python -m uvicorn server:app --port 8001` from a scratch folder with `PYTHONPATH` set to the repo and `index.html` linked there) needs every key of `.env` set in its environment, blank or dummy: `load_dotenv()` never overrides a set variable, and a real key there would make real calls (a real bot token, a real long-poll); its ledger is the scratch folder's `data/providers.db`. Restarting the server reloads recent chat history into context, so a bad past answer can resurface; `POST /reset` (the UI's "New chat") clears it. After editing `javid.py`/`server.py`, restart the server — it doesn't hot-reload.
